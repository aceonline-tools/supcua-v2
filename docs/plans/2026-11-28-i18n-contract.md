### C1 as built (deviations from the design text below)

- `Detector` is a struct of two funcs, `{UILanguage func() (uint16, bool); Preferred func() []string}`, not a single func. `Detect()`: Vietnamese primary language id → `vi`; a real non-vi id → `en`; a custom-range/neutral id (`id & 0x3FF == 0`: 0x0C00, 0x1000, 0x1400, 0) or a failed call → the **first** preferred UI language tag decides (`vi*` → `vi`), else `en`. `locale.DefaultDetector` is the production wiring (Windows) and is replaceable in tests.
- The catalogue is imported by relative path (`frontend/src/i18n/catalog.ts` → `../../../locale/catalog.json`), no Vite alias. `frontend/vite.config.ts` and `frontend/sim/run.mjs` (its `configFile:false` dev server) add `fs.allow` so the dev servers can serve the file outside `frontend/`.
- The `ErrorRef` helpers (`frontend/src/i18n/errors.ts`: `toErrorRef`, `errorMessage`) ship in C1 with tests; C3 only migrates the store's fields onto them. Client-only codes `CLIENT_TIMEOUT`, `CLIENT_DISCONNECTED`, `UPDATE_STALE` are in the TS `ErrorCode` union and the catalogue.
- Dead-id check: an id that no chunk references yet carries `"pending": "<chunk>"`; the test fails if a pending id is referenced (drop the marker) or an unmarked id is unreferenced. `error.*` ids (resolved dynamically from codes) and `boot`-scoped ids (served through `BootJSON`) are exempt. A use is `t('id')` / `locale.T("id")` / `locale.TL(l, "id")`, or any quoted string equal to a catalogue id.
- Literal scan scope: **opt-in list** `frontend/src/i18n/migrated.json` (files that are fully migrated; C3-C5 append their files). `frontend/i18n-allow.json` starts empty; entries are `{file, match, reason}`, `reason` in the fixed enum, and a stale entry fails the test.
- The language control is a native `<select>` (`LanguageSetting.svelte`), not a segmented control: the existing icon-coverage and Settings button-count tests assume every button carries an icon and count buttons, and a `<select>` stays clear of both (no edits to those tests, less merge risk with `feat/process-picker`). It adopts `store.settings.language` through an effect; C3 moves that sync to app start so it also covers pages other than Settings.
- Not in C1: `Deps.OnLanguageChanged`, tray, native dialogs, `window.__lang` injection (C2); the Playwright overflow script `frontend/sim/e2e/i18n-layout.mjs` (the scan itself, `frontend/src/lib/layoutScan.ts`, is in C1; the harness lands with C3 when there are surfaces to scan); `-selftest` forcing `en` (C2).
- `settings.update` sets `locale.Set` after persisting (so native code sees the new language even before C2 wires the UI-thread tray update) and emits `settings.changed{fields:["language"], language}`.
- Additive edits outside the original C1 list, forced by the new required `language` field: `frontend/src/api/mock.ts` (seed `language: 'en'`), `frontend/src/api/fixtures/settings.json`, `frontend/src/api/fixtures.test.ts` (field count 12 → 13), `frontend/sim/run.mjs` (one `fs.allow` option).

Inventory: `inventory.json` (310 entries) lives with the design artefacts at `/tmp/supcua-i18n/` and is not part of the repository; this file keeps its method and limits (§10).

| Topic | Decision |

## 1. Locale model

**Values.** `type Locale string` (Go) / `'en' | 'vi'` (TS). Closed set; adding a language is a catalogue + `Supported` change only.

**Persistence.** New field in `model.AppConfig`: `Language string \`json:"language,omitempty"\`` (`model/config.go:27`). Empty = never chosen. `DefaultConfig()` leaves it empty (so first launch detects). `config.json` is already extensible: `storage/config_store.go:32` uses plain `json.Unmarshal` (unknown/missing fields are fine).

**Settings API.**
- `SettingsDTO.language`: always the *effective* value (`"en"|"vi"`), never empty.
- `SettingsPatch.Language *string` (`bridge/dto.go:92`), validated by `locale.Parse`; invalid → `invalidSetting("language")` (`INVALID_SETTING`, field `language`), same path as `theme` (`bridge/settings.go:98-106`).
- `settings.changed` fields include `"language"`; the event struct gains `Language string \`json:"language,omitempty"\`` (additive; `bridge/dto.go:165`) so receivers apply the value without a refetch race.
- `language` is in the `immediate` set, never `RestartRequired`.

**Resolution (`locale.Resolve(persisted string, detect Detector) Locale`)**, in order:
1. `Parse(persisted)`: trim, lower-case, take the primary subtag before `-`/`_`; `vi`/`vi-VN` → `vi`, `en`/`en-US` → `en`. Anything else (empty, `"fr"`, `"VI "`→`vi`, `"123"`) → not valid, go to 2.
2. `detect()` (Windows UI language, see below): primary language id `0x2A` (`LANG_VIETNAMESE`, `langid & 0x3FF`) → `vi`; any other id, `0`, or detector failure → `en`.
3. `en`.

**Unsupported or corrupt persisted values.** Treated as unset: resolve as above, **do not rewrite** the file until the user picks a language (never destroy data on a read path). A wrong-typed `language` (e.g. a JSON number) makes the *existing* `json.Unmarshal(&AppConfig)` fail exactly like any other mistyped field today (`config load failed`, `main.go:370`); the early reader (§2) decodes through `map[string]json.RawMessage` and so never panics or blocks startup on a bad value.

**Not persisted on first launch.** The detected value is not written until the user chooses (a user who later changes the Windows language and never touched the selector follows it; the Settings selector shows the effective value). Decided (Q1): not persisted.

**Windows detection boundary.** (As built: a struct of two funcs, see "C1 as built"; the sketch below is the original single-func shape.)
```go
// locale/detect.go
type Detector func() (langID uint16, ok bool)
// locale/detect_windows.go  (kernel32!GetUserDefaultUILanguage via windows.NewLazySystemDLL; no error return)
// locale/detect_other.go    returns (0,false)  — tests and non-Windows builds
```
`Resolve` and `Early` take the `Detector` as a parameter; production wires `locale.WindowsUILanguage`; tests inject fakes (table: 0x042A→vi, 0x0409→en, 0x0000→en, `ok=false`→en, 0x082A?→ not vi-VN but still primary 0x2A → vi).

**Documented limits (not a reopen).**
- `GetUserDefaultUILanguage` returns the *first* entry of the user's preferred display-language list; a user with `[en-US, vi-VN]` gets `en`. Intended: the first-choice display language wins.
- Windows UI English + region/keyboard Vietnamese → `en` (we follow the UI language, per requirement).
- Supplemental locales (Windows 11 languages without a legacy LCID) can return a custom id (`0x1000`-range / `0x1400`) → `en`. `vi-VN` has a real LANGID (0x042A), so the target case is unambiguous. Mitigation (decided, Q2): when the id is in the custom range, or the call fails, fall back to the first tag of `GetUserPreferredUILanguages(MUI_LANGUAGE_NAME)` and match `vi*`.
- Selftests (`-selftest`, `-selftest-production`) **force `en`** regardless of config/detection (existing self-tests drive the UI by English `aria-label`, e.g. `ui/selftest_update_check_windows.go:67`, `ui/selftest_settings_hotkey_windows.go:44`). A new flag `-lang vi` overrides this for the i18n self-tests only.

## 2. Early native UI (before any web UI exists)

New package `locale/` (Go). `locale.Current()` is an `atomic.Pointer`-backed global read by tray, native dialogs and the editor-window title; written by `locale.Set` (startup and on change). A global is justified: the native dialogs run before any dependency graph exists.

`func Early(dir string, detect Detector) Locale`: opens `dir/config.json` (≤1 MB read cap), decodes only `language` via `map[string]json.RawMessage`, ignores every error, returns `Resolve(...)`. Stored with `locale.Set` immediately.

## 3. Message catalogue

**Single source:** `locale/catalog.json` (Go package dir, so `//go:embed catalog.json` works with no generation). Format (flat, id-sorted, 1 entry per id):

```jsonc
"tray.exit":        { "en": "Exit", "vi": "Thoát", "scope": ["native"] },
"main.scriptCount": { "en": { "one": "{n} script", "other": "{n} scripts" },
                      "vi": { "other": "{n} script" }, "scope": ["web"] },
"loader.starting":  { "en": "Starting…", "vi": "Đang khởi động…", "scope": ["web","boot"] },
"settings.processName": { "en": "Game process name", "vi": "Tên tiến trình game",
                          "tight": true, "ctx": "Settings row title, ~180px column" },
"error.name_taken": { "en": "a script with this name already exists", "vi": "…", "scope": ["web"] }
```
Fields: `en`, `vi` (string or plural object keyed by CLDR categories; `en` needs `one`+`other`, `vi` only `other`), `scope` ⊂ {`web`,`native`,`boot`} (default `["web"]`), optional `tight` (opt-in to the strict length check), `ctx` (translator note), `same` (set `true` + `why` when vi is intentionally identical, e.g. `OK`).

**IDs.** `<surface>.<camelName>`, surface ∈ `common|main|settings|editor|update|licence|loader|tray|native|evt|error`; bridge codes are `error.<code lower-case>` (`error.hotkey_conflict`). Ids are stable forever: rewording changes the value, never the id; an id is never reused for a different meaning. The inventory `id` column is the proposed first-pass id.

**Params.** `{name}` placeholders; values are `string|number`; both languages must use the *same set* (parity test). Plural selection param is always `n`. User content (script names, paths) is passed as a param, never concatenated.

**TS typing (generated mirror of types only).** `scripts/i18n-gen.mjs` (≈40 lines, Node, no deps) reads `catalog.json` and writes `frontend/src/i18n/ids.gen.ts`:
```ts
export type MsgId = 'common.ok' | 'main.scriptCount' | …;
export interface MsgParams { 'main.scriptCount': { n: number }; 'tray.exit': {}; … }
```
`t<K extends MsgId>(id: K, ...p: {} extends MsgParams[K] ? [] : [MsgParams[K]]): string`. A vitest test fails if `ids.gen.ts` differs from regenerated output (`npm run i18n:gen -- --check`). The *values* are never generated into TS: the app imports the JSON directly (`import catalog from '@i18n/catalog.json'`; `@i18n` alias → `../locale`; add `server.fs.allow` in `frontend/vite.config.ts`).

**Go typing.** `locale.T(id string, p ...Param) string` and `locale.TL(lang, id, p...)`. Compile-time constants are not generated; instead an AST test (`go test ./locale`) walks the module and fails on any `locale.T("literal")` whose id is missing from the catalogue, and on any `SetText/SetToolTip/MessageBox/UTF16PtrFromString` argument in `ui/`, `main.go` that is a string literal (allowlisted: log text, class names, URLs).

**Runtime (frontend).** `frontend/src/i18n/i18n.svelte.ts`: `export const i18n = new (class { lang = $state<Locale>(initial()); set(l){…} })()` and `export function t(id, params)` which reads `i18n.lang` (so any template/`$derived` that calls `t` re-renders on switch; fine-grained, no remount, **no `{#key lang}`**). Fallback chain per call: catalogue[lang] → catalogue.en → the id itself (and a dev-only `console.warn`). `Intl.PluralRules(lang)` for plurals.

**Library choice: none.** Rejected `svelte-i18n`, `typesafe-i18n`, `i18next`/`i18next-icu`: ≥30 KB runtime plus an ICU parser, async loaders and store plumbing for 2 languages × ~310 strings with `{x}` + one plural pattern; Svelte 5 runes give reactivity for free; Go native strings need a second implementation regardless. Revisit only if a third language needs gender/complex plurals or a translator workflow (XLIFF/Weblate) is adopted. Cost of the choice: catalogue JSON (~65 KB raw at 310 ids × 2 languages) is bundled into the single JS file; acceptable for a local WebView2 app.

## 4. Errors

**Principle.** Go keeps stable codes (`bridge/errors.go:11-30`); its English `message` stays for logs and as last-resort fallback only. The UI renders `t('error.'+code.toLowerCase())` at presentation time.

**`ErrorRef`.** `type ErrorRef = { code: ErrorCode; field?: string; params?: Params; fallback?: string }`. `toErrorRef(e: unknown): ErrorRef` replaces `errorText` (`store.svelte.ts:39-41`): `ApiError` → `{code, field, fallback: e.message}`; anything else → `{code:'INTERNAL'}` mapped to `error.something_wrong`.
`errorMessage(ref)`: `t('error.'+ref.code.toLowerCase(), ref.params)`; missing id → `ref.fallback` → `t('error.internal')`. For `INVALID_SETTING` with `field`, `error.invalid_setting.<field>` if it exists, else generic.

**Retained errors re-render.** Every field that now holds English text holds an `ErrorRef` instead, rendered in the template via `errorMessage(...)` (which reads `i18n.lang`):

| Today | After |
|---|---|
| `store.error: string`, 15 assignments `this.error = errorText(e)` (`store.svelte.ts:176,233,283,296,308,319,342,412,430,451,460,476,491,502,513`) and literals (`:231` "Editor already open") | `error: ErrorRef \| null`; literal → `{code:'EDITOR_WINDOW_BUSY'}`-style ids (`error.editor_already_open`) |

| `editor.windowFailed` text (`:158`: `The editor stopped; your draft was saved to ${path}` / `…: ${e.message}`) | map by existing `stage` field (`timeout|measure|renderer|create|shutdown`, `editor_window.go:272,278,342,624,634`) to `error.editor_stage_<stage>`; compose `error.editor_stopped` / `error.editor_stopped_recovered{path}` at render time. `message` is ignored by the UI |

**Dispatcher errors.** `ApiError` for an unknown code (older host / future code) → `fallback` (server English) → `error.internal`. Never a blank.

## 5. Live switching

1. Settings selector (`LanguageSetting.svelte`, new file, mounted in the *Appearance* section after Theme) calls `store.setLanguage(l)` → `settings.update{patch:{language}}`.
2. Go (`bridge/settings.go`, next to theme): validate → `Config.Update` → `locale.Set(l)` → `emit(settings.changed{fields:['language'], language:l})` → `Deps.OnLanguageChanged(l)` (new optional hook; `main.go` wires it to `webUI.Post(tray.ApplyLanguage)` and to the editor-title update).
3. `settings.changed` is already `TargetBoth` (`bridge/targets.go:21`): **main and editor windows both receive it.** Each window's store handles it (`store.svelte.ts:139`) by calling `i18n.set(language)`; `i18n.set` also sets `document.documentElement.lang`. New windows get `window.__lang` at creation (§2.7) and `settings.get` confirms.
4. **Editor window.** Switching only touches the `$state` read by `t()`; DOM nodes, the editor store (draft), selection, caret and focus are not recreated, so unsaved edits and focus survive. Required test: open editor, type into a field, dispatch `settings.changed{language}`, assert the field value, `document.activeElement` and selection range unchanged and labels changed. Note: while an editor window is open the main window is disabled (`EnableMain(false)`, `bridge/editor_window.go:256`), so the UI cannot switch language during an editor session; the event path is still implemented and tested (robustness, other windows, future callers). Native editor title: `UI.SetEditorTitle(gen, title)` on the UI thread.
5. **Tray (UI thread).** `ui/tray.go` currently retains only `dragAction` and `autoAction`; it must retain all seven actions (`toggleStatus`, `show`, `toggleOverlay`, `drag`, `auto`, `process`, `exit`) in a struct. `ApplyLanguage()` runs on the UI thread (posted via the existing UI-thread dispatcher the tray already relies on, `webUI.MainWindow()` owner) and only calls `SetText` on the retained actions + `UpdateTooltip()`. It must not rebuild the menu: checked state (`autoAction.SetChecked`), `Triggered()` callbacks and item order (`Insert(1/2, …)`) are preserved by construction. `SyncOverlayLabel()` and `UpdateTooltip()` read `locale.T` so later state changes stay in the right language. Tooltip is capped at 127 UTF-16 units (`NOTIFYICONDATA.szTip`): truncate the *script name* with `…` first (Vietnamese is longer).
6. Update dialog / pending toasts / Settings update-status: derived from state + `t()`, so they follow automatically.
7. **No restart needed.** Not live: the OS-drawn "Already Running" and startup-failure boxes (shown once, before UI), and the already-open overlay (not translated).
8. Persistence: written by step 2 before any event; a crash right after still starts in the new language.

## 6. Exclusions (never translated, never in the catalogue)

- Overlay status words `RUN`, `IDLE`, `DISABLED` (GDI overlay, `ui/overlay.go`).
- User content: script names, group names, action values, paths, process names, hotkey *key names* as stored (`Ctrl + Alt + F8`, `RCtrl`), version strings.
- Diagnostic logs and startup-log stage names (`log.Printf`, `stages.Mark`, `res.Step`, `diag.ts`, `otrace`), including the `stage` echoed into the load-timeout box (`{stage}` param, English).
- Brand `supcua`, `supcua-v2`, `WebView2`, `GitHub`, `JSON`, `WebView2 Runtime` product names.
- Selftest driver strings and CSS selectors.
All of these live in `frontend/i18n-allow.json` / Go allowlist with a `reason` (§7).

## 7. Checks (each runnable in CI unless marked Windows)

**7.1 Parity test (fails on any missing translation).** `go test ./locale` and `vitest src/i18n/catalog.test.ts` (same rules, two runners): (a) every id has non-empty `en` and `vi`; (b) identical `{param}` sets; plural shape rules (§3); (c) `vi != en` unless `same:true`+`why`; (d) no `TODO`/`XXX`/empty/leading-trailing space/double space; (e) `error.*` has an entry for every `Code*` in `bridge/errors.go`, `ui/webview/rpc/rpc.go`, and every TS `ErrorCode` + client codes; (f) every id referenced in `frontend/src` and Go exists, and every id is referenced (dead ids fail); (g) `en` of each id equals `locale/en-baseline.json` — the English captured from 55f2851 (ids with a baseline) — so "English text unchanged" is test-enforced, and Go `messages[...]` English equals catalogue `error.*.en`; (h) `ids.gen.ts` is fresh; (i) soft: `len(vi) > 1.5*len(en)+4` for `tight:true` ids fails, others warn.

**7.2 Literal-string detection.** `frontend/src/i18n/literals.test.ts` using `svelte/compiler` `parse` and `typescript` (both already devDeps) — no new dependency. Flags: Svelte `Text` nodes containing a letter (outside `<script>/<style>`); attributes `aria-label, aria-description, aria-placeholder, aria-roledescription, title, placeholder, alt` (static or expression with string/template literal); string/template literals in markup expressions; in `.svelte.ts/.ts` (non-test) string literals that contain a space+letter or start upper-case and are assigned to / returned for fields or functions named `error|status|message|label|title|text|hint|failed`, or passed to the toast/error setters, or used in a ternary feeding such a binding; and validation return values (`keySequence.ts`, `hotkeyRecorder.svelte.ts`). Exclusion list `frontend/i18n-allow.json`: `[{file, match, reason}]`, `reason ∈ {brand, key-name, code, css, diagnostic, user-content, overlay-status, dev-only, test-fixture}`. The test fails on (i) any unlisted hit, (ii) any **stale** allowlist entry that matches nothing. List changes are visible in review diffs. Go side: AST test described in §3. Scope/limit: heuristic; it cannot see strings built at runtime from data (e.g. server-provided `message`), which §4 handles by rule.

**7.3 Overflow / clipping at FHD effective 100/125/150%.** `frontend/sim/e2e/i18n-layout.mjs` (Playwright, same `PLAYWRIGHT_DIR` convention as `sim/e2e/check.mjs`; run against `SIM_TAGS=none npm run sim` or `sim:build`). ## 10. Inventory: method and limits

Frontend entries come from a heuristic extractor over `frontend/src/**/*.svelte`, `index.html` and non-test `.ts` (text nodes, accessible attributes, string literals), reviewed by hand and augmented with interpolated texts; Go entries are located by grep and verified line numbers.
